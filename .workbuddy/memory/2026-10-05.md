### 新增关键技术结论（踩坑记录，务必遵守）

**FluentAvalonia 3.1 的 `FAContentDialog`：**
- `DefaultButton` 枚举是 `FAContentDialogButton.None/Close/Primary/Secondary` —— **没有 `OK`**，要「确定」用 `Close`。
- **没有 `XamlRoot` 属性**（那是 WinUI 3 的概念）。必须用 `ShowAsync(Window)` 或 `ShowAsync(TopLevel)` 重载传入宿主窗口，无参 `ShowAsync()` 不适用。
- 返回值枚举 `FAContentDialogResult.None/Primary/Secondary`（**没有 `Close`**）。所以「点关闭/确定」拿到的是 `None`，判「用户确认」应判 `== Primary`。

**Avalonia 12.1 剪贴板是全新 API（重大变更）：**
- `IClipboard` 只有 `SetDataAsync(IAsyncDataTransfer)` / `TryGetDataAsync` 等底层方法，**没有** `SetText`/`GetText`。
- 文本读写走扩展方法 `Avalonia.Input.Platform.ClipboardExtensions`：
  - 写：`clipboard.SetTextAsync(string)`（**必须 `using Avalonia.Input.Platform;`**）
  - 读：`await clipboard.TryGetTextAsync()`（返回 `string?`，无内容返回 null）
- 拿 Clipboard：`TopLevel.GetTopLevel(control)?.Clipboard`（窗口内用 `this`，ViewModel 里用 `AppLifetime.MainWindow`）。

**控件命名差异：**
- Avalonia 核心**没有** `ProgressRing`，环形进度用 FluentAvalonia 的 **`FAProgressRing`**（有 `IsActive`，非 `IsIndeterminate`）。
- `FANavigationView.IsBackButtonVisible` 是 **bool**（不是 WPF 的 Visibility）。
- `FANavigationViewItem.IconSource` **不能直接写字符串**，必须给 `IconSource` 对象。XAML 里写：
  ```xml
  <ui:FANavigationViewItem.IconSource>
      <ui:FASymbolIconSource Symbol="Play" />
  </ui:FANavigationViewItem.IconSource>
  ```
  可用类型：`FASymbolIconSource` / `FAFontIconSource` / `FABitmapIconSource` / `FAImageIconSource` / `FAPathIconSource`。

**其他：**
- `ComboBox`/`TextBox` 的占位符属性在 Avalonia 里是 **`Watermark`**（WPF 是 `PlaceholderText`）。
- `IsVisible` 一律 bool（不是 Visibility.Collapsed）。
- 打开文件对话框：`StorageProvider.OpenFilePickerAsync(FilePickerOpenOptions{ ... })`，取本地路径用 `item.TryGetLocalPath()`。
- `Window.ShowDialog<TResult>(owner)` / `ShowDialog(owner)` 返回 `Task`，`void` 方法里要 `_ = ...` 丢弃。

### 又一批关键 API 结论（FluentAvalonia 3.1 导航，务必遵守）

**`FANavigationView.ItemInvoked` 不能在 XAML 里挂！**
- 它是 CLR 事件，委托类型是 **`EventHandler<FANavigationViewItemInvokedEventArgs>`**（不是 `TypedEventHandler`，虽然内部定义存在）。

- 正确做法（官方 Sample `MainView.axaml.cs` 同款）：代码里订阅
  ```csharp
  RootNavigation.ItemInvoked += OnNavigationItemInvoked;
  // 签名：
  private void OnNavigationItemInvoked(object? sender, FANavigationViewItemInvokedEventArgs args)
  ```
- 取被点击项：`args.InvokedItemContainer is FANavigationViewItem item` → `item.Tag`。

**`FASymbolIconSource.Symbol` 必须用 `FASymbol` 枚举值**，且**不能写 `IconSource="Play"` 字符串**。正确 XAML：

<ui:FANavigationViewItem Content="启动" Tag="LaunchPage">

## 续三：Avalonia XAML 与 WPF 的差异清单（移植页面必须逐条对照）

这些差异**编译期不一定报错，但运行期 UI 会错**，是本项目移植的坑点清单：

| WPF 写法 | Avalonia 正确写法 | 备注 |
|---|---|---|
| `ListBox.ItemContainerStyle` | `ListBox.Styles` + `<Style Selector="ListBoxItem">` | **Avalonia 没有 ItemContainerStyle** |
| `<Style TargetType="X">` | `<Style Selector="X">` | 全项目所有 Style 都如此 |
| `Style.Triggers` + `DataTrigger` | 用绑定的 `!` 取反：`IsVisible="{Binding !SomeBool}"` | Avalonia 无 Style.Triggers |
| `Visibility="Collapsed"/"Visible"` | `IsVisible="False"/"True"` | 一律 bool |
| `Visibility` 绑转换器 | 直接绑 bool 表达式 | 见上 |
| `Padding` on ItemsControl region | 同 | — |
| `Grid RowDefinitions="Auto,*"` 短语法 | 支持，推荐 | 比 `<Grid.RowDefinitions>` 简洁 |
| `Source="/Assets/x.png"` | `Source="avares://VibrantbitLauncher.Avalonia/Assets/x.png"` | 图片资源必须写全 avares |
| `ui:SymbolIcon Symbol="Xxx24"` | `TextBlock` 里用私有区字形 `Text="&#xE7B8;"` 或 `FAFontIconSource` | **Avalonia 无 SymbolIcon 控件**；简单场景用 `TextBlock`+字形码。常用：`&#xE7B8;`(BoxMultiple) `&#xE8FA;`(PersonAdd) |
| `Image.Clip` + `EllipseGeometry` | 同，可用 | 圆形头像 |
| `MouseLeftButtonUp="Handler"` | `PointerReleased="Handler"` | 事件名不同 |
| `App.Services.GetService(typeof(T))` | `AppServices.Provider?.GetService(typeof(T))` | 新服务定位入口 |
| `Application.Current.Windows.OfType<X>()` | `AppLifetime.MainWindow` | 别再去遍历窗口集合 |
| `Wpf.Ui.INavigationService` | `AppNavigation.Current`（自建 `INavigationService`） | — |
| `ui:SnackbarPresenter` | 不再需要；轻提示由 `AppServices.Notifications` 统一管 | 主窗口右下角宿主 |
| `WindowStartupLocation="CenterOwner"` | 同，可用 | — |

**`Loaded` 事件**：Avalonia `UserControl` 有 `Loaded`，签名 `(object?, RoutedEventArgs)`。
**`RadioButton` 分组**：用 `GroupName`，行为一致。

## 续四：AccountPage + SettingsPage 完成

### 又一批 API 结论（重要）

**`SymbolIcon` 不存在！** FluentAvalonia 3.1 里对内联图标控件叫 **`FASymbolIcon`**（不是 `SymbolIcon`）。而 `FASymbolIconSource` 是给 `IconSource` 属性（如 nav item）用的，两者不可互换。
- 内联图标：`<ui:FASymbolIcon Symbol="Home" />`（`ui` = `using:FluentAvalonia.UI.Controls`）
- 已验证可用 Symbol 值：`Home` `Edit` `Setting` `OpenFile` `Refresh` `Play` `Contact` `Download` `Clock` `People` `Add` `Delete` `Save` `Image` `Link` `List` `Pause`
- 报错特征：`AVLN2000: Unable to resolve type SymbolIcon from namespace using:FluentAvalonia.UI.Controls`

**`ComboBox.DisplayMemberPath` 在 Avalonia 不存在！**
- WPF 的 `DisplayMemberPath="Display"` → Avalonia 必须写 `ComboBox.ItemTemplate` + `<DataTemplate x:DataType="..."><TextBlock Text="{Binding Display}" /></DataTemplate>`。
- （简单场景也可依赖对象 `ToString()`，但显式模板更稳。）
- 报错特征：`AVLN2000: Unable to resolve suitable regular or attached property DisplayMemberPath on type Avalonia.Controls.ComboBox`

**ItemsControl 内取外层 DataContext 的命令（Avalonia 写法）：**
```xml
Command="{Binding $parent[UserControl].((vm:SettingsPageViewModel)DataContext).SelectAccentCommand}"
```
- WPF 的 `RelativeSource={RelativeSource AncestorType=ItemsControl}` → Avalonia 用 `$parent[UserControl]`（注意 `$parent` 后跟类型名，取 `ItemsControl` 也可以但常取更外层的 UserControl），并用 `((vm:XxxViewModel)DataContext)` 做类型转换以便编译期绑定校验。
- 需要 `xmlns:vm="using:VibrantbitLauncher.ViewModels.Pages"`。

**色板「选中环」的实现（替代 WPF `ControlTemplate.Triggers` + `DataTrigger`）：**
- 用 `Button.Tag` 绑定 bool，再写样式 `Style Selector="Button[Tag=True] /template/ Border#Ring"` 设置 `BorderBrush`。
- XAML：
  ```xml
  <Button ...><Button.Tag><Binding Path="IsAccentSelected" /></Button.Tag>
      <Button.Styles>
          <Style Selector="Button[Tag=True] /template/ Border#Ring">
              <Setter Property="BorderBrush" Value="{DynamicResource TextFillColorPrimaryBrush}" />
          </Style>
      </Button.Styles>
      <Button.Template>...<Border x:Name="Ring">...</Border></Button.Template>
  </Button>
  ```

**ComboBox / TextBox 占位符：** Avalonia 12.1 中 `TextBox.Watermark` **已过时**（AVLN5001 警告），改用 **`PlaceholderText`**。（先前笔记写反了，已更正。）

**`ListBox` 定制项容器：** `ListBox.Styles` + `<Style Selector="ListBoxItem">`，`Template` 里用 `<ControlTemplate><ContentPresenter /></ControlTemplate>`（注意 Avalonia 的 `<Setter Property="Template">` 内 `ControlTemplate` 不带 `TargetType`）。

### 新踩到的坑（务必记住）

**① `UserControl.Resources` 里不能放 `<Style>`！**
必须用 **`<UserControl.Styles>`**。放 `Resources` 里报：
`AVLN3000: Unable to find suitable setter or adder for property Resources ... for argument Avalonia.Styling.Style`
- `Resources` 只放资源实例（转换器 `x:Key`、画刷、Thickness 等）。

**② Avalonia `CheckBox` / `ToggleButton` 没有 XAML `Checked` / `Unchecked` 事件属性！**
`AVLN2000: Unable to resolve suitable regular or attached property Checked on type Avalonia.Controls.CheckBox`

### 通用教训（Avalonia/WPF 都适用）

# 设置页完善（v1.0.5.3）

**用户需求**：「请你完善所有的设置页面的内容」。排查后发现**不是内容缺失，而是设置页整页绑定全部落空**——界面看起来一片空白。

## 根因（三个叠加问题）

1. **`SettingsPage` 没有设置 `DataContext`**（核心）
   - `SettingsPage` 是 DI 单例，构造函数里只订阅了 `DataContextChanged`，**没有** `DataContext = _viewModel`。
   - 结果它继承了主窗口的 `MainWindowViewModel`，而页面绑定的 `CurrentThemeText` / `SelectedJava` /
     `LogSummary` / `AccentPresets` 等属性只在 `SettingsPageViewModel` 上 → 全部绑定失败，界面空白。
   - 日志证据：`Could not find a matching property accessor for 'Xxx' on 'MainWindowViewModel'`。
   - 对照：其余页面（MultiplayerPage/DownloadCenterPage/VersionManagePage…）都在构造里 `DataContext = vm`，唯独设置页漏了。

2. **反射绑定解析不了类型转换语法**
   - 色板 / 壁纸三处 `Command` 写成 `{Binding $parent[UserControl].((vm:SettingsPageViewModel)DataContext).XxxCommand}`。
   - 本工程 `AvaloniaUseCompiledBindingsByDefault=false` → 绑定走反射实现，**反射绑定无法解析 XAML 的 `vm:` 命名空间前缀**，
     模板一实例化就抛 `ArgumentException: Unable to resolve type vm:SettingsPageViewModel`。
   - 修法：改用 `{Binding $parent[ItemsControl].DataContext.XxxCommand}`（反射绑定可解析）。

3. **内置壁纸缩略图空白**
   - `WallpaperOption.ImagePath = "/Assets/bg1.png"`（应用内相对路径）直接绑 `Image.Source`，
     Avalonia 解析不了这种相对资源 URI。
   - 修法：`WallpaperOption` 加 `Preview`（构造时 `AssetLoader.Open(new Uri("avares://VibrantbitLauncher.Avalonia" + path))` → `Bitmap`），
     XAML 改绑 `Preview`；`ImagePath` 仍保留用于持久化 / 实际应用背景。

## 附带修复
- `EnumToBooleanConverter` 从 `internal` 改 `public`（XAML 实例化要求可公开访问），并让 Convert/ConvertBack 对坏输入返回安全值不抛异常。
- 主题色 / 渐变终点色「选中环」原用 `Style Selector="Button[Tag=True]"`——Avalonia 属性选择器拿 Boxed bool 做字符串比较不可靠。
  改在 `AccentPreset` 上加 `AccentRingBrush` / `GradientRingBrush`（选中不透明色、未选中透明），模板一次直接绑定。
- 日志 `ListBox` 加回 `VirtualizingStackPanel`（上千条不卡）。
- Java 下拉项补文本样式类；壁纸缩略图加圆角；`OnChangeTheme` 参数改 `string?` 消除空引用警告。

## 验证方法（重要，可复用）
无界面环境（本会话）用**环境变量注入式冒烟脚本**：
1. 在 `App.axaml.cs` 的 `OnFrameworkInitializationCompleted` 里临时加：读 `VBL_SMOKE` 环境变量 → 设
   `Avalonia.Logging.Logger.Sink = new SmokeLogSink()`（把 `Binding` 区日志转 Serilog）→ `mainWindow.Opened` 时

2. 跑 `VBL_SMOKE=SettingsPage ./VibrantbitLauncher.Avalonia.exe`，grep 日志里的

## 通用教训
- **每个 DI 提供的 UserControl 页面，构造函数里必须 `DataContext = _viewModel`**，否则静默继承父级 DataContext，
  整页绑定落空，且只有在该页被打开时才在日志暴露 `... on MainWindowViewModel`。
- **关闭编译绑定（`AvaloniaUseCompiledBindingsByDefault=false`）时，不要在 `{Binding}` 里写 `((vm:Xxx)DataContext)` 类型转换** ——
  那是编译绑定语法，反射绑定解析不了 `vm:` 前缀，运行时抛异常。取父级 VM 用 `$parent[ItemsControl].DataContext.Xxx`。
- `Image.Source` 绑定资源图片要用 `avares://` 绝对 URI 或预加载的 `Bitmap`，`/Assets/xxx.png` 这种相对路径解析不了。
