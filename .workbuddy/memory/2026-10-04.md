# 2026-10-04

## 通读项目：VibrantbitLauncher 架构速查

WPF / .NET 10 (net10.0-windows7.0) 的 Minecraft Java 版启动器，Fluent 风格 (WPF-UI 4.3)，AGPL-3.0。

**分层**：App.xaml.cs (Generic Host + DI + Serilog) → Views → ViewModels (CommunityToolkit.Mvvm) → Services/Helpers → 外部依赖。

**关键约定 / 坑（代码注释里反复强调）**：
- 全局单例状态放在 `MainWindowViewModel.MainModel`（static MainModel），SettingsService 读写它。
- 配置持久化：`SettingsService`（`settings.json` 存 BaseDirectory，含全部账户，直接用 MinecraftLaunch 的账户类型）；目录取 `SettingsService.ResolveMinecraftFolder()`，页面里不要硬编码 `./.minecraft`。
- 主题：统一蓝色 `#FF0078D4`，不跟随系统；颜色用 WPF-UI 语义画刷，勿硬编码。
- DI 注册：所有 Page 必须注册进 `App.xaml.cs` 的 services，否则导航 `GetPage` 返回 null。
- 页面间通信：`WeakReferenceMessenger`（如 "NavigateTo" / "McVersionForManage" / `DownloadHubTabMessage`）。

**自实现绕过第三方库 bug 的地方**（勿改回库调用）：
- `JavaHelper` — 替代 `JavaUtil.EnumerableJavaAsync()`（空路径候选会抛异常导致检测不到 Java）。
- `FabricDownloader` — 替代 `FabricInstaller`/`MinecraftResourceDownloader`。
- `ModrinthSearchService` — 替代 `ModrinthProvider.SearchAsync`（支持 modpack/resourcepack/shader）。
- `MinecraftVersionCache` — 进程内版本清单缓存 + `Preload()` 预热。
- `RunPageViewModel.LaunchMinecraftManually` — 手工拼 java 命令行启动（绕过 MinecraftLaunch runner）。

**启动核心**：`Views/Pages/RunPage.xaml.cs` → `RunPageViewModel.RunMinecraft` → 解析版本/匹配 Java/刷新微软 token → 手工起进程 → 退出码非 0 弹 `CrashAnalysisWindow`。

**已知待办/半成品**：`MultiplayerPage.xaml.cs`（EasyTier 联机逻辑整块被注释掉，UI 在但功能停摆）；`MultiplayerPageViewModel` 空实现；`SettingsPageViewModel.AppVersion` 文案还写着 "ColorfulCraftLauncher"。

## 修复：切换主题色时控件不实时刷新（「切主题色要刷新主题」）

**现象**：改 `SystemAccentColor`/`AccentFillColorDefaultBrush` 等资源后，`ui:Button Appearance=Primary` 等控件颜色不跟着变（实测按钮 `Background` 一直停在旧值 `#FF006ABB`），要重启才生效。

**根因（WPF-UI 4.x 的资源机制）**：
- 控件取色链是 `Button.Background ← {DynamicResource AccentButtonBackground} ← Color 资源 AccentFillColorDefault`。
- `AccentButtonBackground` 定义在 WPF-UI **主题词典**（Light.xaml/Dark.xaml）里，是**词典加载时**求值出来的；`ApplicationAccentColorManager.Apply()` **不会**更新 `AccentButtonBackground`。
- 所以只写 `SystemAccentColor`/`AccentFillColorDefaultBrush` 不改 `AccentFillColorDefault`(Color) 也没用。

**修复（`Services/SettingsService.cs`）**：
1. `ApplyTheme()` 顺序改为 **先 `ApplyAccent()` 写主题色 → 再 `ApplicationThemeManager.Apply(theme, WindowBackdropType.Mica, updateAccent:false)` 重载主题词典 → 最后刷 scrim**。词典重载会用新主题色重算 `AccentButtonBackground` 等派生画刷。
   - `updateAccent:false` 必须传，否则 WPF-UI 会先把强调色重置成系统色。
   - ⚠️ 顺序不能反：先重载词典再写主题色 = 白改。
2. `ApplyAccentCore()` 里 **Color 版本和 Brush 版本都要写**：新增 `AccentFillColorDefault/Secondary/Tertiary`（Color），原有的 `*Brush` 保留。
3. 新增统一入口 `ApplyAccentChange()`（= `ApplyTheme()`），设置页改主题色 / 渐变 / 恢复默认都调它；`ApplyAccent()` 降级为「只写资源键」的内部方法。

**验证方法（可复用）**：临时在 `MainWindow` 的 `Loaded` 里挂 `DispatcherTimer`，改主题色前后各做一次 `RenderTargetBitmap(this.Content)` 存 PNG，并直接读控件 `Background` DP + `Application.Current.TryFindResource(...)` 打日志；再逐像素 diff 两张 PNG。
- 结论：修复后 `AccentButtonBackground` 与「启动游戏」按钮 `Background` 一起由 `#FF006ABB → #FF8A2626`，diff 命中 6698 px（导航指示条/标题强调条/主按钮）。
- 注意：`RenderTargetBitmap` 不受屏幕遮挡/用户点击影响，比全屏截图可靠（全屏截图会被同时在操作 App 的人干扰）。
- 调试完成后务必删掉临时 timer、还原 `MainWindow.xaml.cs`。
