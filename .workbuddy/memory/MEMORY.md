# VibrantbitLauncher 项目长期约定

## 版本号规则（用户明确要求，必须遵守）

**每次更新都要在 CHANGELOG 里的上一版本号后面加一个新的版本号，并且同步更新 `VibrantbitLauncher.csproj` 的 `<Version>`。**

**四段式版本号**（`主.次.修订.小补丁`）：

- **小版本**（功能改进、问题修复、UI 打磨等日常更新）→ **末尾再加一段**：`1.0.4` → `1.0.4.1` → `1.0.4.2` → `1.0.4.3` …
- **大版本**（重大功能 / 架构级变更）→ **第三段 +1、末尾补丁归零**：`1.0.4` → `1.0.5`（而不是 `1.0.4.5`）。

> ⚠️ 注意不要混淆：小版本是**多一段**（`1.0.4` → `1.0.4.1`），不是第三段进位（`1.0.4` → `1.0.5`，那是大版本）。

具体做法：
1. 在 `CHANGELOG.md` 顶部（`# 更新日志` 引言之后）新增一节 `## [x.y.z.n] - YYYY-MM-DD`，把本次改动写进该节；**不要**把新改动塞进已有的旧版本小节。
2. 标题后的日期用当天日期。
3. 小节按 `### 新增 / ### 改进 / ### 修复 / ### 说明` 分类，沿用既有写法（每条 `- **加粗标题**：说明`）。
4. 同步把 `VibrantbitLauncher.csproj` 的 `<Version>` 改成同一个号。
5. 版本号唯一来源是 `csproj` 的 `<Version>`，启动日志横幅与设置页「关于」都从这里读（走 `AssemblyInformationalVersion`，去掉 SourceLink 的 `+<commit>` 构建元数据）。
6. 显示逻辑目前按三段式处理（`App.xaml.cs` / `SettingsViewModel.cs`），改成四段号（如 `1.0.4.1`）后需确认这两处的格式化不会把末尾段吃掉。

版本历史：`1.0.3`（2026-10-04）→ `1.0.4`（2026-10-04，多人联机）→ `1.0.4.1`（2026-10-05，下载中心打磨）。
